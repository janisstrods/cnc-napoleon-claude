# C&C: Napoleonics — Plan 6B: Miniature Art Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Original procedural SVG miniatures for every nation and unit code of battles 001–015 (one figure per block, as in Ancients) and a mounted general per nation. Each has a period-correct silhouette, nation palettes and an arm badge with a block count. All are wired into the board once Plan 2B's contract swap has landed.

**Architecture:** The art is built in a new, self-contained module `src/art/nap/`. It imports only React, `src/art/color.ts` and `src/engine/codes.ts`. Its own dev gallery is `#/gallery/figures`. The Ancients art and `src/art/token.tsx` are left alone, because Plan 2B's T1c rewrites `token.tsx` with placeholder figures keyed by `UnitKey`. Task 1 lays down the vocabulary, every file with stubs, the token frame (base plate, slots, badge, Guard marker) and the gallery. Tasks 2–6 replace the stubs, one family each, in two parallel lanes. Task 7 is gated on Plan 2B T1c: it makes the public `UnitToken`, `LeaderToken` and `UnitIcon` delegate to the new art for every art key, and pins the result with a hash test. The drawing code reads data only: the figure specs and nation looks decide everything, and the drawing code never tests a nation or unit code.

**Tech Stack:** TypeScript 5.6, React 18 (SVG), Vitest 2 with `react-dom/server` for markup tests, headless Chrome via `scripts/shot.sh` for board-scale checks.

**Spec:** `design/superpowers/specs/2026-11-17-cnc-napoleonics-design.md` ("Miniature art" under Extras; "Look and feel"). Unit list: `design/survey.md` §2.1. Codes: `src/engine/codes.ts` (Plan 2A Task 2). Background on the T1c swap: `/Users/janisstrods/Gamemaking/cnc-napoleonics-research/plan2-prep.md` §2 and §5.

## Global Constraints

- **Original art only.** Every figure is drawn in code from primitives. No GMT artwork, no tracing, no copying from images, no image or font assets. Uniform choices come from written descriptions and general period knowledge, and are hedged in comments where sources differ.
- **Isolation:** files under `src/art/nap/**` import only `react`, other `src/art/nap/**` files, `src/art/color.ts` and `src/engine/codes.ts`. No Ancients art module, no engine types beyond `codes.ts`, no scenario data. Tasks 1–6 never edit `src/art/*.tsx`/`*.ts` outside `nap/`.
- **Data, not names:** drawing code never branches on a nation or unit code. Codes and nation names appear as string literals only in `nap/keys.ts`, `nap/nations.ts` and `nap/specs/**`.
- **Frame:** a figure is drawn facing right in a local frame with its feet (or wheels, or hooves) at (0,0), with y negative upwards. It is lit from the screen's upper left, and side light layers are mirrored through `FacingRightCtx`, as in the Ancients `src/art/draw.tsx` header. A foot figure is about 30 units tall. Headgear is drawn in a **head-local frame**: origin at the centre of the head, head radius 2.4, facing right. Foot, rider, crew and bust all place their heads in that frame, scaled.
- **Token:** centred on (0,0) of a pointy-top hex of radius 50 (`HEX_R`). The base plate sits inside the hex. The top-right corner is kept clear for an attached leader at offset `{ x: 29, y: -28 }`. Figures are removed back rank first. A figure keeps its slot and its paint index as the unit is depleted.
- **Board scale** for every visual check is 0.75 px per SVG unit: a hex about 65 px wide, which is what a 1400×1000 window gives the board. Readability at that size outranks detail.
- **Nation and block colours:** blue blocks for France, red for Britain, brown for Portugal. The Allies stand on the Portuguese brown (the scenario booklet's instruction for 014–015).
- **Dev servers:** lane A uses port 5181, lane B uses 5182, and Task 7 uses 5173. Start one with `npx vite --port <port> --strictPort` (in the background). Do not add launch configs. Screenshots go to `${TMPDIR:-/tmp}/ccn-6b-*.png`, are never committed, and the implementer must open each one and say in the report what it shows.
- Every commit leaves `npm run typecheck` clean and `npm test` green.
- British spelling in comments, labels and identifiers we introduce (`colour`, `grey`, `armour`). SVG, DOM and CSS attribute names stay as they are.
- Commits are path-limited (`git add <paths>`), and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Models:** Sonnet implements each task; Opus reviews each task. The reviewer also opens the task's screenshot.

## Review Focus

1. **Look-alike units at board scale.** A player must tell FR/LN from FR/LT, FR/GR from FR/OG, FR/HC from FR/CU, BR/LN from BR/RI and FA from HA in a 65 px hex. This is pinned by the colour-stripped "shapes differ" tests in Tasks 2–5 and each task's board-scale screenshot.
2. **Left-facing units.** The army facing left is drawn mirrored. Its badge text and pips must not be mirrored, and its light must still fall from the upper left. Pinned by Task 1's test that the badge is identical in both facings, and by the mirrored row in every screenshot.
3. **Depleted units.** At 3, 2 and 1 blocks, the same painted figure stays in the same front slot, and a gun is the last piece left. Pinned by Task 1's slot-stability test and Task 5's gun-last test.
4. **A unit key with no art.** An `SP/*` key, or a Plan 2B `UNIT_KEYS` row not in the survey, must render the T1c placeholder, never crash and never show a blank hex. Pinned by Task 7's fallback test.
5. **Long leader names.** "Prince of Orange" or "Kellermann" must sit inside the name ribbon. Pinned by Task 6's ribbon-width test.
